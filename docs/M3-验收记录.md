## 二、隐私承诺从"一句话"变成"两半各有机器守"

承诺已从「零网络请求」改为「**默认不联网、可选联网**」。关键在于：这句话的两半各由**不同手段**守住，而且都可复现。

| 承诺 | 由什么守 | 证据 |
| --- | --- | --- |
| **只有一个网络出口** | **静态**：`check-conventions.ps1` 扫描全部 `src`，除 `WinKit.Platform/Ai/DeepSeekClient.cs` 外任何文件出现 `HttpClient`/`WebRequest`/`WebClient`/`HttpWebRequest`/`Socket`/`TcpClient` 即失败 | `越界 0 处` |
| **默认不联网** | **动态**：`ai-gating-e2e.ps1` 实测未启用时点 AI 按钮不建窗口、不发请求 | 6 条断言全过 |
| **发送前必须预览** | **结构**：AI 调用统一走 `AiLauncher.ShowPreview`，没有绕过它的入口（唯一例外是"测试连接"，见下） | 代码结构 + 第 9 步 |
| **只发最少必要的数据** | **逐字断言**：`PromptBuilder`/`TextRedactor` 是纯函数，`AiPrivacyTests`（41 个用例）断言"到底发送了什么" | 302 全绿之一部分 |
| **密钥不明文落盘** | `ApiKeyStore` 用 DPAPI(CurrentUser) + 附加熵加密，**不写进 config.json**（配置会被导出迁移，密钥不该跟着走） | 单元测试 |

> 设计原则：**只能靠自觉的隐私承诺不是承诺**。所以把"没有别的联网代码"做成一条命令能验证的事实，
> 把"未启用时不发请求"做成每次验收都跑的实测步骤。

## 三、测试挖出的四个真实隐私缺口（全部关闭）

前三个由 `AiPrivacyTests` 挖出，第四个由实现界面的 agent 自己发现。

| # | 缺口 | 证据 | 修法 |
| --- | --- | --- | --- |
| 1 | `ForProcess` 把可执行文件的 `FileDescription` 一起外发 | prompt 里出现「由 alice 编译」 | **移除该参数**（而非忽略）—— 编译期强制调用点复核 |
| 2 | `ForHealthReport` **完全不做脱敏**，`HealthItem.Detail` 是自由文本 | prompt 里出现 `C:\` 乃至 `C:\Users\alice\projects\secret-client` | 新增 `SanitizeFreeText`（Redact → RemovePaths） |
| 3 | `ForCleanupRules` 不过滤 `rule.Description` 里的路径 | prompt 里出现 `C:\Windows\Temp`、`C:\Windows\Minidump` | 同上 |
| 4 | 调用方可用 `row.Name ?? row.DisplayName` 把文件描述当"进程名"绕回通道 1 | 代码审查 | 改为只用 `row.Name`，取不到就什么都不发 |

**共同点**：这四处的披露说明都写着"不含…"，而行为相反。**披露与行为不一致比不做披露更糟** —— 用户是照披露做决定的。

### 3.1 新增 `RemovePaths`，与 `Redact` 分工明确

- `Redact`：**保留路径结构**，只抹用户名/机器名/疑似密钥 —— 日志诊断必须看到路径才能定位问题；
- `RemovePaths`：把整段路径换成 `<路径>` —— 用于**路径对模型毫无价值**的场景（体检、清理规则）。

### 3.2 缺口"目录名里的客户名/项目名"刻意没用正则修

`D:\Clients\acme-corp\secret-project\` 里的业务名称**不可能靠正则判定**，加更多模式只会给人"已处理干净"的错觉。改为：

- 日志路径**有意保留**（诊断需要），
- **如实改写披露文案**："日志里的文件路径会被保留…请在上方编辑框检查一遍，删掉你不希望外发的目录名后再点发送"。

配合预览窗口的可编辑能力，把不可自动判定的部分**交还给用户**，而不是假装处理干净了。

## 四、另一个由实现者自己发现的漏洞

**用户在预览框里粘贴的内容会绕过脱敏**（`PromptBuilder` 只在构造请求时脱敏一次）。

修法：把脱敏搬进 `UserMessageText` 的 setter（幂等、同源），从而保住 **"界面显示的内容 == 实际发送的内容"** 这个等式 —— 而不是偷偷在发送时改内容。这个等式的价值在于：用户看到的就是会发出去的，不存在"看着安全其实改了/没改"的不确定性。

| 清理页发送"扫描到 N 项"而非勾选量 | 与 `PromptBuilder` 文案"共扫描到 N 项"自洽，但可能大于本次要清的项数 |

## 六、复现方法

```powershell
# 一键跑完 9 项验收（含 AI 闸门，不需要 API Key）
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\verify-all.ps1

# 只验 AI 闸门
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\ai-gating-e2e.ps1

# 只验隐私边界（逐字断言"到底发送了什么"）
& "C:\Program Files\dotnet\dotnet.exe" test tests\WinKit.Core.Tests\WinKit.Core.Tests.csproj --filter "FullyQualifiedName~AiPrivacyTests"
```

> ⚠️ 所有 `.ps1` 必须保留 UTF-8 BOM：Windows PowerShell 5.1 读无 BOM 的 UTF-8 脚本会按 GBK 解码，中文注释直接变成语法错误。
