## 1. 项目定位

一句话：**把"系统维护 + 文件批处理 + 开发运维 + 硬件监控"四类高频操作，收进一个双击即用、不装、不联网、不耍流氓的图形界面。**

### 1.1 目标

1. **一个窗口解决 80% 的日常排查**：不用再开 5 个 PowerShell 窗口敲 `netstat -ano | findstr`。
2. **危险操作可解释、可预览、可撤销**：清理类工具最大的信任问题是"删了什么我不知道"，本工具用"扫描 → 预览 → 执行 → 报告 + 一键撤销"解决。
3. **便携零残留**：配置跟随程序目录，卸载 = 删文件夹。
4. **技术可审计**：每个操作都能导出为等价的 PowerShell 命令，用户看得懂、学得会、能自己复核。

### 1.2 明确的非目标（和功能同等重要）

这些**明确不做**，避免产品滑向"流氓优化软件"：

| 不做的事 | 原因 |
| --- | --- |
| "一键加速""内存释放""注册表深度优化" | 不可解释、不可回滚、收益存疑甚至为负（`EmptyWorkingSet` 只是把内存推到页面文件，反而更慢） |
| 驱动级 / 内核级操作 | 需要签名驱动，风险与维护成本远超收益 |
| 联网云查杀、账号体系、遥测上报 | 隐私承诺是核心卖点，一旦联网就说不清 |
| 绕过 UAC、隐藏自身、开机驻留 | 与恶意软件行为特征重合，会被杀软针对 |
| 静默修改注册表/服务 | 所有写操作必须用户可见、可撤销 |
| "清理 Prefetch 提升性能" | 反效果，会拖慢下次启动。可以做扫描展示，但默认不清理且标注风险 |

## 3. 环境与已核查事实

### 3.1 本机实测（2026 环境快照）

| 项 | 值 |
| --- | --- |
| 操作系统 | Windows 10 专业版 22H2（内部版本 **19045**） |
| 架构 | AMD64 (x64) |
| 系统 Python | **3.12.8** @ `C:\Python\Python\python.exe`（`py -0p` 默认 3.12） |
| 其他 Python | uv 管理的 3.14.3、3.15.0a6 |

### 3.2 由事实推出的三条技术基线

1. **开发基线锁 Python 3.12**。PySide6 与 PyInstaller/Nuitka 在 3.14/3.15 上生态尚不成熟，3.15 还是 alpha，不用于发布。用 `uv` 建项目级虚拟环境，避免污染系统 Python。
2. **Win10 19045 是必须支持的基线，不能用 Win11 独占能力**。具体后果：无 Mica/Acrylic 材质、Qt6 在 Win10 上默认 `windowsvista` 样式（在 Win11 上又会变成 `windows11` 样式）→ **统一用 Fusion 样式 + 自绘 QSS 主题**，才能保证两个系统上观感一致、深色模式可控。
3. **必须是 Qt Widgets 路线，不用 QML**。本工具 90% 的界面是表格、树、列表（进程表、文件表、日志），Widgets 的 `QTableView + QAbstractTableModel` 天然合适；QML 在大量表格数据下反而更费劲，且要额外打包 QtQuick 模块（体积 +20~30MB）。

## 4. 设计原则（不可妥协）

| # | 原则 | 落地方式 |
| --- | --- | --- |
| P1 | **危险操作必须 预览 → 确认 → 可撤销** | 统一四步交互（第 7 章）；所有写操作进"撤销中心" |
| P2 | **只做可解释的优化** | 每个优化项必须给出"做了什么 / 为什么 / 依据"；不接受"魔法" |
| P3 | **UI 永不阻塞** | 任何 >200ms 的操作进 `QThreadPool`，带进度与取消按钮 |
| P4 | **便携零残留** | 配置写程序目录；只在明确需要时写 `%LOCALAPPDATA%` |
| P5 | **最小权限，按需提权** | 默认标准权限启动；需要管理员的按钮带盾牌图标，点击才提权 |
| P6 | **默认不联网，可选联网** | 唯一可能联网的是**可选启用**的 AI 助手（DeepSeek），且必须由用户主动点击发送并确认；发送前逐字预览将要发送的内容。全项目只允许 `DeepSeekClient.cs` 一个文件使用网络 API，由 `scripts/check-conventions.ps1` 机器校验 |
| P7 | **体积与启动时间是硬约束** | 每加一个依赖都要过"体积评审"；不引入 numpy/pandas |

### 4.1 关于 P7 的一条硬性技术决策

**不引入 numpy / pandas / pyqtgraph。**

理由：numpy 单独就 +15~20MB 体积 + 0.3~0.5s 启动时间，而本项目只需要画实时折线图和磁盘树图。这两者用 `QPainter` 自绘分别约 150 / 200 行代码即可，零依赖、零体积代价、还能完全控制视觉风格。这是一个典型的"用一点开发量换 20MB 体积"的划算交易。

## 5. 总体架构

### 5.1 分层

```
┌──────────────────────────────────────────────┐
│  ui/       Qt 界面层（唯一 import PySide6 的层） │
│            页面 / 控件 / 自绘图表 / 主题        │
├──────────────────────────────────────────────┤
│  tasks/    功能任务层（插件）                   │
│            每个工具 = 一个 TaskModule           │
│            声明：元信息 / 页面 / 权限 / 撤销支持  │
├──────────────────────────────────────────────┤
│  platform/ 系统访问层（Q: 有没有 Qt？无）        │
│            win32.py(ctypes) / registry.py       │
│            / powershell.py / fs.py / elevate.py │
├──────────────────────────────────────────────┤
│  core/     纯 Python 内核（可单测，无 Qt 无 Win） │
│            日志 / 配置 / 撤销引擎 / 扫描引擎     │
│            / 规则引擎 / 哈希 / 格式化            │
└──────────────────────────────────────────────┘
```

**关键纪律：`core/` 和 `platform/` 里不允许出现 `import PySide6`。** 这样核心逻辑可以用纯 pytest 快速测试（毫秒级），而不必启动 Qt 事件循环；也让将来换 UI 框架的成本降到最低。

### 5.3 插件（TaskModule）机制

每个功能页声明为一份**元信息 + 一个页面类**，由注册表自动收集，主窗口导航据此生成：

| 字段 | 作用 |
| --- | --- |
| `id` / `title` / `group` / `icon` | 导航与命令面板 |
| `requires_admin: bool` | 是否显示盾牌图标、是否走提权路径 |
| `supports_undo: bool` | 是否在撤销中心出现 |
| `keywords` | 全局搜索（Ctrl+K）匹配 |
| `headless: callable` | 允许 `--task=<id>` 无界面执行（供提权子进程与脚本化调用） |

收益：新增功能不用改主窗口代码；`headless` 同时解决了"提权执行"和"命令行可脚本化"两个需求。

### 5.4 线程与任务模型

- 统一 `TaskHandle`：`progress(int, str)` / `is_cancelled()` / `log(level, msg)` / `result`。
- 扫描类任务分块产出结果（边扫边显示），不等到全部扫完才刷 UI。
- 取消是**协作式**的：任务在每个循环迭代检查 `is_cancelled()`，保证点取消后 200ms 内停下来。
- 铁律：**UI 线程内只做渲染，不做任何文件遍历、注册表读取、子进程调用。**

### 5.5 权限模型（本项目的技术难点）

**默认以标准用户权限启动**，只有明确的"管理员动作"才提权。三种策略：

| 策略 | 适用 | 说明 |
| --- | --- | --- |
| A. 整程序提权 | 极少用 | 通过重启自身（`ShellExecuteW runas`）实现，界面会闪一下 |
| B. 单动作提权子进程 | **主力方案** | 同一个 exe 以 `--task=<id> --args=<json> --out=<tmpfile>` 无界面运行，干完写结果文件退出 |
| C. 引导用户授权 | 兜底 | 需要交互式 UAC 的场景，直接提示用户手动操作 |

**B 方案的一个必须提前知道的坑**：通过 `ShellExecuteW` + `runas` 启动的提权进程**无法回传 stdout/stderr**（不继承管道）。因此提权子进程的结果必须走**临时文件或命名管道**，并且：
- 结果文件路径由父进程生成随机 token 名，防止被其他进程预置伪造结果；
- 父进程轮询文件出现 + 校验 JSON 结构与 token，超时（默认 120s）则判失败；
- **提权侧只接受白名单动作 + 结构化参数，绝不接受任意命令行字符串**（否则就是一个自带的 UAC 绕过后门）。

### 5.6 系统访问技术分层（重要技术决策）

| 数据需求 | 首选方案 | 理由 |
| --- | --- | --- |
| 进程 / CPU / 内存 / 磁盘 / 网络 实时数据 | **psutil** | 唯一必需的第三方系统库；快、跨平台、多数无需管理员 |
| 进程挂起/恢复 | `psutil.suspend()/resume()` | psutil 已封装 `NtSuspendProcess`，不必自己碰未文档化 API |
| 高频注册表读写 | **`winreg`（标准库）** | 零依赖 |
| 回收站删除、提权、`WM_SETTINGCHANGE` 广播 | **`ctypes`** | 零依赖 |
| 冷路径硬件信息（主板/内存条/显卡/磁盘/电池） | **PowerShell `Get-CimInstance` → JSON** | 零依赖、结果可缓存，避免为 WMI 引入 pythonnet/pywin32 |
| 回收站"删除到回收站" | `send2trash` 或 ctypes `SHFileOperation` | 体积极小；优先自己用 ctypes 以免多一个依赖 |
| 图片批量处理 | **Pillow**（可选模块） | 约 +3MB，可接受 |
| 媒体转码 | ❌ 不内置，检测外部 `ffmpeg` | ffmpeg 约 80MB，与体积预算冲突 |
| 高速 WMI 轮询 | ❌ 暂不引入 pythonnet | 保护体积预算；冷路径已由 PowerShell 覆盖 |

**PowerShell 调用的工程细节（避免踩坑）**：
- 一律用 `-NoProfile -NonInteractive -ExecutionPolicy Bypass -EncodedCommand <base64 UTF-16LE>`：彻底绕开中文路径/引号的转义地狱。
- 输出统一 `ConvertTo-Json -Depth 5 -Compress`，Python 侧 `json.loads`，按需归一化"单对象 vs 数组"（PowerShell 单元素会退化成对象）。
- 所有调用带超时（默认 15s）与重试；结果按 TTL 缓存（硬件信息 TTL 10 分钟），避免频繁 fork 子进程拖慢界面。
- 一次调用尽量批量取多个类，而不是每个字段一次调用。

## 7. 统一交互范式

### 7.1 四步流程（所有写操作强制遵守）

```
① 扫描  →  ② 预览  →  ③ 执行  →  ④ 报告
   只读       列出每一项      带进度可取消    结果 + 撤销按钮
              含大小/路径
              可勾选/排除
```

**② 预览是产品的灵魂**：必须逐项展示"要动什么"，显示合计影响（释放 X MB / 影响 Y 项），允许逐项取消勾选，并把用户的排除项记入白名单。

### 7.2 操作危险分级

| 级别 | 定义 | 交互要求 |
| --- | --- | --- |
| **L0 只读** | 扫描、读取、监控 | 直接执行 |
| **L1 可逆写入** | 删到回收站、改名、改配置 | 预览 + 单次确认 + 记入撤销中心 |
| **L2 难逆写入** | 彻底删除、改系统环境变量、禁用服务、改 hosts | 预览 + 输入确认词 + 自动备份 + 撤销中心 |
| **L3 高危** | 结束系统进程、清理更新缓存、改系统 PATH | 预览 + 输入确认词 + 明确风险说明 + 建议先建还原点 |

### 7.3 撤销中心设计

| 操作类型 | 撤销方式 |
| --- | --- |
| 删文件 | 优先移入**回收站**；撤销 = 记录原路径并从回收站还原 |
| 重命名 / 移动 | 记录 (原路径, 新路径) 映射表，逐条反向执行 |
| 注册表改写 | 改前把原键值序列化为 JSON 备份；撤销 = 回写原值 |
| 禁用启动项 | 不删原键，只备份值 + 移入隔离位置；撤销 = 还原 |
| 服务启动类型 | 记录原 `Start` 值；撤销 = 回写 |
| 环境变量 | 备份原值；撤销 = 回写 |
| 清理垃圾文件 | **不可撤销**（已删文件无法恢复）→ 因此 L1 也必须先预览、且默认走回收站 |

**事务日志 schema（JSONL，每行一条）**：

```json
{"ts":"2026-01-01T12:00:00+08:00","batch":"a1b2c3","task":"cleanup.temp",
 "level":"L1","action":"delete","target":"C:\\Users\\x\\AppData\\Local\\Temp\\a.tmp",
 "size":10240,"method":"recyclebin","result":"ok","undo":"restore_from_bin",
 "elevated":false,"app_version":"0.1.0"}
```

### 7.4 白名单与保护

- 内置**不可删路径黑名单**：`C:\Windows`、`C:\Program Files*`、`C:\ProgramData`、`System32`、用户"文档/桌面/图片"根目录等，默认拒绝任何删除操作，需要显式在设置里解锁。
- 用户可加白名单（目录/文件名模式），扫描时直接跳过。
- 单次批量删除数量或体积超阈值（如 >5000 项 或 >10GB）时，强制二次确认。

## 11. 技术选型与打包发布

### 11.1 依赖清单（目标：依赖越少越好）

| 依赖 | 用途 | 体积 | 必需性 |
| --- | --- | --- | --- |
| `PySide6-Essentials` | GUI 框架 | 较大（打包后主要体积来源） | 必需 |
| `psutil` | 进程/系统/网络数据 | ~1MB | 必需 |
| `Pillow` | 图片批量处理 | ~3MB | 可选模块 |
| `send2trash` | 移入回收站 | ~50KB | 可选（可自己用 ctypes 实现） |
| `numpy` / `pandas` / `pyqtgraph` | — | 20MB+ | **❌ 明确不引入** |
| `ffmpeg` | 媒体转码 | ~80MB | **❌ 不内置，检测外部** |

> **PySide6 选包注意**：应安装 `PySide6-Essentials` 而非完整版 `PySide6`。Essentials 覆盖 QtCore/QtGui/QtWidgets/QtNetwork/QtSvg/QtSql 等本项目所需模块，不含 QtWebEngine/QtMultimedia/QtCharts 等大块头。**该选型需在打包阶段实测确认所需模块齐全**（本规划基于其模块清单，未在本机实际安装验证）。

### 11.2 打包方案对比

| 方案 | 冷启动 | 体积 | 杀软误报 | 评价 |
| --- | --- | --- | --- | --- |
| PyInstaller `--onefile` | **慢（3~10s）**，每次启动都解压到 `%TEMP%\_MEIxxxx` | 中 | **高** | 最符合"单文件"字面要求，但启动体验差 |
| Nuitka `--onefile` | 较快 | 较小 | 中 | 编译期长、兼容坑多，作为备选 |
| PyInstaller `--onedir` + 7-Zip SFX 自解压 | **首次慢，之后秒开** | 中 | 中 | ⭐ **推荐主力方案** |
| 纯 `--onedir` 打 zip（绿色版） | 秒开 | 大（未压缩） | 低 | 作为并列发布物 |

### 11.3 推荐发布策略

同时发布两个产物，覆盖两种使用习惯：

1. **`WinKit.exe`（SFX 自解压单文件）** —— 主推。双击后首启解压到 `%LOCALAPPDATA%\WinKit\runtime\<版本号>\`（一次性），随后启动内层 exe，之后每次启动都是秒开。版本号变化时自动解压新目录，并清理旧版本。
   - 满足"双击即用、只有一个文件"的直觉；
   - 规避 PyInstaller onefile 每次冷启动解压的老毛病；
   - 解压目录可预测，便于排查与杀软白名单。
2. **`WinKit-0.1.0-portable.zip`（绿色目录版）** —— 解压即用、秒开、零安装，适合放 U 盘或内网分发。

**为什么不直接用 `--onefile`**：PyInstaller onefile 每次启动都要把几十 MB 解压到临时目录，且临时目录随机，是"启动慢 + 杀软误报高"的主要来源。SFX 方案用一次性的解压成本换掉了每次启动的成本。

### 11.4 打包瘦身清单

- 只装 `PySide6-Essentials`；
- 排除用不到的 Qt 模块：`QtWebEngine*`、`QtQuick*`、`QtQml*`、`Qt3D*`、`QtCharts`、`QtMultimedia*`、`QtPdf*`、`QtDesigner`、`QtTest`；
- 排除标准库里的大块：`tkinter`、`unittest`、`test`、`pydoc_data`、`lib2to3`；
- **不使用 UPX**（压缩后误报率显著上升，且影响启动速度）；
- 用 `--onedir` 产物做体积分析，逐项确认每个 DLL 是否必要。

### 11.5 杀软误报应对（分发阶段最大风险）

| 措施 | 说明 |
| --- | --- |
| 不用 UPX | 首要 |
| 不自我修改 | 不做自解压后覆盖自身等行为 |
| 不写敏感位置 | 不碰其他程序的目录与注册表 |
| 提交误报申诉 | 向 Microsoft Defender 等提交 FP 报告 |
| 代码签名 | **最有效的解法**，但需要付费的代码签名证书（见第 16 章决策点） |
| 文档透明 | 说明产物如何构建、脚本开源，降低用户与杀软厂商疑虑 |

## 12. 配置与数据

### 12.1 便携模式探测

启动顺序：

1. 若 exe 所在目录可写 → 配置写 `.\WinKit-data\`（**便携模式**，U 盘可用）；
2. 否则（装在 `Program Files` 等只读位置）→ 回退 `%LOCALAPPDATA%\WinKit\`；
3. 状态栏显示当前模式与配置路径，设置页可"一键清除所有数据"。

### 12.2 目录内容

```
WinKit-data/
├─ config.json          # 设置（主题、白名单、阈值、采样间隔）
├─ journal.jsonl        # 操作日志（可轮转）
├─ backups/             # 注册表/启动项/环境变量备份（JSON）
├─ undo/                # 撤销事务数据（重命名映射、回收站索引）
├─ logs/                # 运行日志（含崩溃日志）
└─ cache/               # 硬件信息等缓存（可随时删）
```

### 12.3 配置约束

- `config.json` 带 `schema_version` 字段，升级时做迁移；未知字段保留不丢。
- 写入一律**原子替换**（写临时文件 → `os.replace`），避免掉电/崩溃导致配置损坏。
- 备份文件带时间戳，保留最近 N 份（默认 20），超出自动清理。
