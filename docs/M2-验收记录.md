## 二、本轮实现的 4 个 ★ 项

| 功能 | 实现要点 |
| --- | --- |
| **磁盘读写曲线** | 走 Windows 性能计数器 `PhysicalDisk(_Total)` 而不是 WMI（WMI 单次 50~300ms，做不了 1 秒采样）。首次创建计数器要 10~50ms，因此在后台线程预热，避免首帧卡顿 |
| **一键体检** | 评估逻辑做成**纯函数**（`HealthCheck.Evaluate(HealthInputs)`）：Core 不碰系统，因此能在毫秒级单测里跑遍所有边界。**只扣分不加分**，没问题就是 100 分。页面**只扫描、绝不写**，且不申请提权 |
| **结束进程树** | `.NET` 拿不到父进程，只能问 WMI，所以是冷路径：**一次查询**取回全部 `(PID, 父PID)` 再在内存建树。返回顺序**子先父后** —— 反过来先杀父进程会让子进程变孤儿继续跑，看起来像"没杀干净"。黑名单覆盖**整棵树**（任一命中即整棵拒绝），且确认框把"将结束多少个进程、它们是谁"列清楚 |
| **管理员权限按需申请** | 把已打通但空置的提权通道接到真实动作上：提权清理 |

## 三、提权通道为什么值得单独验证

**提权子进程本质上是一个"以管理员身份跑某段逻辑"的入口。如果不验证拒绝路径，它就是一个自带的 UAC 绕过后门。** 所以 [elevated-task-e2e.ps1](../scripts/elevated-task-e2e.ps1) 的逆向用例比正向用例更重要，且实测全部被拒：

```
disposal=Permanent  → "提权清理不接受彻底删除，只允许隔离区或回收站"
数据目录下的路径    → "没有通过校验的待清理项（…或位于 WinKit 数据目录之下）"
非法 base64/非 JSON → 安全失败，且仍然回传结果文件
未知任务 id         → "尚未实现该提权动作：evil.task"
```

设计上的几道闸门：

1. **只接受结构化参数，绝不接受任意命令字符串**。
2. **拒绝 `Permanent`** —— 提权 + 不可撤销的删除是最危险的组合，从设计上排除。用**白名单**（只列允许值）而不是"排除 Permanent"，这样将来新增枚举成员默认落在拒绝侧。
3. **拒绝数据目录之下的路径**（防止隔离区自吞）；数据目录**不可解析时 fail-closed**（宁可不做，也不赌"不会碰到隔离区"）。
4. **结果文件只写一次**：内层写失败后不被外层 catch 覆盖，真实失败原因不会被"执行异常"顶掉。
5. **载荷日志只记字符数、不记内容**（路径里含用户名）。
6. **日志归属明确**：提权侧复用同一个 `CleanupExecutor`、写同一份 journal，父进程只更新界面状态、**不重复记日志** —— 否则撤销中心会出现两份记录，而父进程那份没有 `UndoKind`、根本撤不了。

## 四、本轮修复的真实缺陷

| # | 缺陷 | 怎么发现的 |
| --- | --- | --- |
| 1 | `DiskIoSampler.Dispose()` 后 `Sample()` 返回 `Available=false`，但 `IsAvailable` 属性仍是 `true` —— 外部看到"属性说可用、方法说不可用"的自相矛盾 | 单元测试 |
| 2 | **我的 API 契约文档写错了**：`ElevatedOutcome` 实现上嵌在 `Elevation` 里，但契约清单里写成了顶层类型。按文档写代码的 agent 自然编译不过 | 集成构建 |
| 3 | 4 次"漏 `using` / 未声明标识符"（B 漏 `WinKit.Core.Tasks`、A 漏 `System.Threading`、D 漏 `WinKit.Platform.Security` 与 `System.Linq`） | 集成构建 |

### 4.1 关于第 3 条：并行开发的流程权衡

**"不许 agent 构建"这条规则避免了 obj 目录争用，代价是把编译错误全部推迟到集成阶段，且四次都是同一类错误。** 这笔交易在当前规模下划算（4 次快速构建就收口了全部 6 个 agent 的产物，比让每个 agent 各建一份隔离 obj 简单），但**如果 agent 数或代码量再大一个量级，就该换成"每个 agent 用独立 `IntermediateOutputPath` 做隔离构建"**。

### 4.2 测试自身的两个 bug（同样值得记录）

- `AssertAllBefore(order, 3, 1); // 1 是根，出现在 GetFullKillOrder 里` —— **注释承认了根只在 `GetFullKillOrder` 里，却对"后代列表"调用**，自相矛盾。
- `Map(2, 1, 3, 2, 2, 3)` —— 父映射是字典，**同一个 pid 写两次会后者覆盖前者**，`2→1` 被 `2→3` 顶掉、根 1 一个子进程都没有。测试想表达的结构用单值父映射根本表达不出来。

## 六、已知限制（诚实记录）

| 项 | 说明 |
| --- | --- |
| 提权清理拿不到逐项结果 | 结果契约只回传一句汇总 + 批次号，因此父进程把"选中项里需要管理员的那些"整批从清单移除；子进程那边失败的项其实还在磁盘上。核实真实结果需看撤销中心批次或重新扫描 |
| 提权批次不进"撤销上一次清理" | 该按钮只认本进程普通清理的批次，提权批次要去「撤销中心」还原（提示文案已如实说明） |
| UAC 期间"取消"按钮无效 | `RunElevatedTask` 内部 `WaitForExit` 不观察 `CancellationToken`，属平台限制 |
| 提权侧未做受保护目录校验 | 父进程扫描器已排除受保护目录，但被篡改的载荷仍可指向 `C:\Windows` 下文件。闭环需把规则的 `AllowProtected` 白名单一起传过去 |
| PID 复用竞态 | 结束进程/进程树在"确认→执行"之间存在 PID 被回收的窗口，.NET 无"PID+创建时间"原子校验 |
| 结束进程树的网络/IO 影响 | 计划快照之后新启动的子进程不会被结束 |
| 温度/SMART 等硬件数据 | 属 ☆ 项，尚未实现；部分机器本身就读不到 |
| 高 DPI / 多显示器 | 清单已加 `PerMonitorV2`，未在真实双屏环境验证 |

## 七、复现方法

```powershell
# 一键跑完 8 项验收
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\verify-all.ps1

# 单独验证提权通道（正向 + 四类逆向）
```

> ⚠️ 所有 `.ps1` 必须保留 UTF-8 BOM：Windows PowerShell 5.1 读**无 BOM** 的 UTF-8 脚本会按 GBK 解码，中文注释直接变成语法错误。
